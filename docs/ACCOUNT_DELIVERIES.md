# Entregas parciales en cuenta corriente

El resumen adicional sólo aparece para ventas cuyo pago preparado deja saldo pendiente. Se limita a «Cobro parcial», referencia de venta, importe aplicado y remanente; las ventas que se cancelan completas no añaden ese bloque. La selección desde Vencimientos ya no muestra un aviso de éxito; conserva el aviso si no puede seleccionarse la venta.

Cobro parcial abre un diálogo compacto con importe recibido, Continuar y Cancelar. No muestra el desglose mientras se ingresa el importe; Continuar prepara la selección y cierra el diálogo, sin registrar pagos. El detalle por artículo distingue saldo pendiente de importe financiado y cobros aplicados; no cambia precios ni el algoritmo de asignación. Escape/Cancelar conserva la selección anterior.

Cobrar desde Vencimientos lleva cliente y venta al selector, selecciona únicamente sus artículos pendientes y abre la página correspondiente. Si dejó de tener saldo seleccionable o necesita conciliar cobros, informa el motivo sin elegir otra venta. Siempre requiere confirmar el cobro. Historial ofrece Todos/Ventas/Cobros; ajustes de precio, aumentos manuales y anulaciones se conservan en Todos y no se confunden con ventas o recibos.

Se conserva el pago manual por venta/artículo, completo o parcial. «Entrega a cuenta» abre un campo de importe; «Preparar entrega» reemplaza sólo la selección del borrador y propone cubrir ventas por fecha ascendente. A igual fecha usa ID de venta y luego ID de artículo para un reparto estable. Usa importes pendientes, no precios originales ni cantidades: puede cancelar artículos completos y una parte del último. No paga artículos ya saldados ni altera precios.

Acepta pesos como `180000`, `180.000`, `180.000,50`, `180000,50` o `180000.50`; calcula en centavos enteros. Una entrega de $180.000 sobre $240.000 deja $60.000. La propuesta aparece en los importes por artículo y en el resumen por venta, con total a cobrar y saldo restante en el panel derecho. Los importes siguen editables antes de confirmar. Abrir una entrega pendiente de preparar invalida temporalmente la confirmación, evitando cobrar una selección anterior por error; cancelar la preparación conserva esa selección.

No se propone reparto cuando existen cobros sin asignar, compras mixtas sin conciliar, diferencias entre detalle y saldo o fechas faltantes. Se conservan los circuitos de conciliación y selección manual. Cambiar de cliente/sucursal reinicia la selección; después de cobrar se recarga el saldo. Preparar, cancelar o editar no hace peticiones de escritura.

Al confirmar se envía el mismo contrato existente (importe, medio, artículos e importes, ID idempotente). La API conserva permisos, validación de pertenencia, topes por artículo y cuenta, transacción serializable, ingreso de caja sólo para efectivo con caja abierta y auditoría/comprobante con saldo histórico. No se agregan endpoints ni se infiere una asignación nueva al servidor; éste recibe y valida la selección finalmente confirmada, sea manual o sugerida. No hay cambios de esquema o migraciones.
